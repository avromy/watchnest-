## Design and preserved behavior

Direction: warm family library with premium streaming sophistication. Optimize
family iPad first, Parent phone second and desktop Parent use third. Parent and
child experiences must form one coherent design system, with clear navigation,
consistent icons, typography, spacing, interaction states and accessible controls.

Existing screenshots provide before evidence. They do not freeze the old layout.
Preserve the selected design source identity and representative reference renders
so subsequent implementation and repairs can be compared consistently. Do not
create an artificial Founder approval dependency.

Preserve individual-video approval, approved-library-only child search, sibling
isolation, Parent authentication and PIN controls, mandatory Safe Playback at
UI/API/database boundaries, existing family data, assignments, Collections,
bounded Discover requests and server-authoritative remote timer controls.
YouTube lifecycle, sandbox, CSP and containment must not change for visual effects.
A separately authorized safety repair requires renewed affected safety evidence.

Presentation, navigation organization, reusable components, copy and front-end
workflow ordering within existing APIs are in scope. A component review cannot
certify the integrated product.

## Candidate-bound evidence

Every review packet identifies the source commit/tree, preview URL/deployment,
relevant schema/configuration, test fixture, browser and viewport. Use synthetic
review data and label it accurately. Never publish credentials, browser auth
state or private family data. Keep simulated/provider/physical-device evidence
clearly distinguished.

Capture readable views of these surfaces and their meaningful states:

- Entry: profile picker, optional child PIN, Parent PIN, returning entry and errors.
- Child: Home, realistic large approved Library, Collections, Favorites, Recently
  Added, search and no results, Discover disabled/enabled, request creation,
  success and pending states, loading, empty library, retry/error, profile
  switching and Time’s Up. Cover Simple and Standard modes where they differ.
- Parent: dashboard, URL intake, YouTube search, channels/playlists, metadata
  loading/error/no results, selection/approval/assignment, Library management,
  Collections, Inbox, children/profile editing, timer controls, discovery
  permissions, settings/protection, dialogs and success/error/empty states.
- Player surroundings: visual regression. Actual playback, provider navigation
  and native fullscreen require their own functional and device evidence.

Inspect clipping, overflow, wrapping, navigation, keyboard/form scrolling, dialog
containment, card density, image crops, reachability and hierarchy. Stress long
video titles, long profile names, many Collections, zero items, statuses and busy
or error controls. Common touch targets must be at least 44×44 CSS px. Verify
visible focus, form labels, meaningful accessible names, sensible headings,
keyboard reachability, reduced motion and readable contrast.

## Independent qualification

Builder checks must be followed by independent technical/security, visual,
responsive, accessibility and product-usability review of the exact candidate.
Reviewers need actual readable browser renders and sufficient evidence to cover
all required screens, visible assets, boundaries and interaction states. Missing
mandatory coverage or unresolved evidence conflicts prevent a clean result.
Inspect professional finish, rhythm, grouping, optical alignment, hierarchy,
crops and contrast as well as functional correctness.

Require independent comparison and adversarial review before the final jury.
The final major-redesign jury consists of **five fresh independent reviewers**;
unanimous PASS is required. Preserve separate verdicts, review identities,
candidate identity, defects, corrections and recheck results. Builder conclusions
or other reviewers’ votes must not contaminate independent verdicts. Supported
material failures block acceptance and must be repaired and independently checked.

Require fresh rendered-browser Stranger review. First impressions must be
recorded before providing the intended workflows, implementation history or prior
review conclusions. Source/API checks cannot substitute for using the application.
The Builder must not self-certify its own cold review.

Cover these distinct journeys:

- Busy returning Parent on phone.
- New or low-confidence Parent entering, adding and assigning a video.
- Younger child browsing and choosing on iPad.
- Older child using search, Favorites and requests.
- Shared-device switching between children and into Parent Mode.

Preserve observed actions, expectations, actual behavior, friction, severity,
screenshots and independent rechecks. Maintain a finite defect register with
explicit dispositions. Material changes invalidate affected earlier evidence.
Detailed reviewer operating instructions remain in the private authorities.

## Production gates and current blocker

Current physical-iPad approved playback, recommendation containment and native-
fullscreen remote-stop acceptance remain pending until genuine new evidence
exists. Chromium tablet simulation cannot satisfy physical-device acceptance.
The affected P0 gate blocks production promotion; finish and preserve independent
UI candidate work while it remains unresolved. Do not weaken Safe Playback or
claim Founder Ready while approved playback fails.

Before promotion:

- Preserve exact rollback commit and deployment.
- Verify no unexpected player, backend or configuration changes.
- Pass relevant functional/security regressions, build, typecheck and lint.
- Complete responsive/accessibility inspection, visual review, design conformance,
  five-person independent jury and Stranger review.
- Resolve material functional, security, visual and usability defects.
- Bind all acceptance results to the final release candidate.

After promotion verify the canonical URL, exact source commit/deployment, hosted
configuration, authorization denials, runtime health and representative workflows.
Do not present a preview as the production deliverable.

Update the existing Run State, Skill Invocation Ledger, current Notion authority,
release/rollback record and project learning with actual results and read back
those writes. Delete clearance requires durable recovery state; it must not rely
on this conversation alone. Do not add internal skill packages to this repository.

approval. Do not claim a notification was sent without confirmed success.
