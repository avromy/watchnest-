## Scoped authority and frozen properties

The new WatchNest design brief and research synthesis are controlling design
inputs. Existing screenshots are BEFORE evidence, not a target the redesign
must reproduce. Once the product team fixes its integrated design direction,
preserve its source commit and representative reference renders with hashes;
compare subsequent responsive implementation/repairs against those identities.
The Founder has delegated design acceptance, so do not insert an approval step.
Figma-specific production is not triggered merely to generate an unnecessary
second representation of the implemented application.

Frozen behavior includes individual-video approval; approved-library-only child
search; sibling isolation; Parent authentication/PIN controls; Safe Playback
mandatory at UI/API/database; existing family data and collections; bounded
Discover requests; server-authoritative remote timer. ChildPlayer lifecycle,
sandbox, CSP and containment code are outside the visual mutation envelope.
Any discovered defect in those mechanisms is a separately scoped repair and
invalidates affected safety evidence.

Writable scope: presentation, navigation organization, reusable components,
copy and front-end workflow ordering within existing APIs. Parent and child
surfaces must be integrated before final acceptance. An isolated component PASS
cannot certify the integrated product.

## Review surfaces and evidence inventory

Record exact source commit/tree, preview URL/deployment, database migration/config
identity, fixture identity and browser/viewport for every evidence unit. Use
synthetic review data; never publish family credentials or browser auth state.
Screenshots of synthetic data must be labeled synthetic, and real provider/device
results remain a separate evidence type.

Capture full-page views plus readable crops for:

- Profile picker, optional child PIN, Parent PIN, returning entry and error.
- Child Home, approved Library with a realistic large collection, Collections,
  Favorites, Recently Added, search results/no results, Discover disabled/enabled,
  request composer/success/pending, loading, empty library, retry/error, profile
  switching, Time's Up. Capture Simple and Standard modes where behavior differs.
- Parent dashboard; URL intake; YouTube search and channel/playlist browsing;
  metadata loading/error/no results; selection/approval/assignment; library
  management; Collections; Inbox; Children/profile editing; timer controls;
  discovery permissions; settings/protection information; success/error/empty
  states and confirmation dialogs.
- Player surrounding UI only for visual regression. Actual media/playback,
  provider navigation and native fullscreen are separately qualified.

Adopt WatchNest-specific viewport matrix: 768×1024 and 1024×768 as iPad anchors;
820×1180 and 1180×820 for larger tablet; 390×844 and 412×915 for Parent phone;
360px narrow stress; 1280×800 and 1440×900 desktop. Inspect intermediate widths
520, 640, 900 and continuous resizing between 360 and 1440px. This matrix is
chosen for the app's stated devices, not inherited from 5T Classes.

At each meaningful width inspect overflow, clipping, line wrapping, navigation,
keyboard/form scrolling, card density, dialog containment, image crops, touch
reachability and hierarchy. Long titles, many collections, zero items, long
profile names, status labels and busy/error buttons are stress specimens.
Minimum common touch target is 44×44 CSS px; ensure visible focus, associated
form labels, meaningful button names, sensible heading order, reduced-motion
support and readable contrast. Keyboard navigation must reach all controls.

## Human-Eye evidence preprocessing and receipt

Before a blind visual reviewer starts, produce a neutral inventory giving each
bounded visible asset an A01…An identity: icons, profile photos/avatars, thumbnails,
brand mark and clipped/decorative shapes. Bind assets to screen/region/viewport.
Supply actual screenshots, readable-scale source-derived crops and structural
records only where needed to resolve boundaries. Each containment-sensitive
asset needs explicit left/right/top/bottom edge resolution. Source/CSS geometry
cannot overrule visibly clipped pixels.

Each final Human-Eye report must include:
SOURCE_IDENTITY; REGION_COVERAGE n/n; BOUNDED_ASSETS n/n;
ASSET_EVIDENCE_CONSUMED A01…An; READABLE_VIEWS required/consumed;
STRUCTURAL_RECORDS required/consumed; EDGE_GATES resolved/required;
APPLICATION_BINDING; UNRESOLVED_CONFLICTS; HUMAN_GATES;
CONFIRMED_DEFECTS; POSSIBLE_CONCERNS; FINAL_RESULT.

Incomplete coverage, missing mandatory views/assets or unresolved conflict
prohibits CLEAN. Inspect rhythm, grouping, optical alignment, hierarchy, crop,
contrast and overall professional finish, not just absence of DOM overflow.

## Independent execution topology

1. Builder integrates code and executes mechanical/functional checks.
2. Fresh blind comparator inspects exact design reference/candidate renders;
   separately an adversarial Reporter applies this contract and produces a finite
   defect register. They do not receive each other's conclusions before freeze.
3. Controller reconciles raw differences against current authority, groups root
   causes and routes bounded repairs. Re-render affected surfaces after mutation.
4. Only after both convergence reviewers are clear, run **five fresh independent
   final jurors**, Mode C. They receive identical candidate/reference packages,
   minimal intended-use/display context and applicable acceptance rubric, not
   Builder conclusions, expected defects, repair history or other juror votes.
   Unanimous PASS is required; any supported failure blocks acceptance. Record
   reviewer context IDs, frozen verdicts, round count and material progress.
5. Run fresh rendered Cold Stranger journeys. Initial inputs are only product
   URL/access/role. Do not supply this contract, implementation checklist,
   intended paths or prior verdicts before true-stranger findings freeze.
6. Give authority only after that freeze for CTO/product/adversarial review.
   The auditor does not repair its own findings. Builder repairs; a fresh
   independent context rechecks affected paths.

With seven total concurrency slots, final five jurors can run after implementation
agents finish. Slots do not justify contaminating reviewers with production
history. A reused context that has already seen Builder work cannot become cold
merely by changing its role label. Use fresh contexts with restricted inputs.

Minimum distinct Stranger journeys: busy returning Parent on phone; new/low-
confidence Parent access and add/assign; younger child on iPad; older child using
search/favorites/requests; shared-device child-to-child and child-to-Parent
switching. Journal visible control, expectation, actual result, friction,
severity and screenshot for every meaningful action. Preserve each report before
loading authority or starting another persona. Do not relabel API/source checks
as rendered interaction.

Final internal packet includes screen-by-screen visuals/commentary, click journal,
friction map, final defect dispositions, persona results and exact-candidate
independent rechecks. Founder review controls are superseded by the current
instruction to make ordinary decisions autonomously; the packet supplies evidence,
not an approval dependency.
