## Findings

1. **Confirmed source crash path: optional browser storage can take down Child Player.** `src/components/child/ChildPlayer.tsx:150-157` reads `window.localStorage.getItem` in a mount effect without a guard. A storage access `SecurityError` escapes the effect into the route error boundary (`src/app/error.tsx:3-20`). A synthetic local reproduction can override Storage.prototype.getItem to throw before loading the player route with authorized local fixtures. This is a credible runtime crash cause, but no observed hosted stack trace currently ties the reported P0 to this path. The write at `ChildPlayer.tsx:790-793` is also unguarded and can throw on quota/policy failure. `Number(null)` additionally resolves to zero, making absent stored preference silently mute playback; distinguish missing storage from an intentional stored zero. Preserve the in-memory default of 60 when persistence is missing/unavailable. Storage is a preference, never an authorization prerequisite.

2. **Requested Preview implementation has no explicit failure state or usable sizing contract.** `src/components/parent/ParentApp.tsx:2191-2221` uses native details/summary, mounting YouTubeEmbed while the disclosure remains closed. `src/components/YouTubeEmbed.tsx:38-66` returns an iframe with optional className, no dimensions, and no error/timeout state. This call provides no className; the existing responsive `.player` rule (`Parent.module.css:134-141`) therefore does not apply. Native details should toggle without a custom handler; source alone does not explain a completely inert disclosure. Inspect the deployed DOM for the `open` attribute, iframe bounding box, hydration/console errors, response CSP, and provider load state. If `open` changes, distinguish disclosure success from provider playback failure. Synthetic iframe load does not establish YouTube playback acceptance. A deliberate Parent preview dialog with lazy mount, responsive size, loading/error feedback, close/focus restoration, and no approval mutation is a bounded repair direction, consistent with Library/Add Video previews already in this component.

3. **Confirmed unhandled async Parent mutation paths.** Inbox new collection Create (`ParentApp.tsx:2271-2282`) calls api/reload outside the shared act error handler. Library Add selected to Collection (`1378-1392`) and Remove selected (`1402-1415`) do the same. A 401, network failure, non-JSON response, or failed reload rejects the event promise without actionable inline feedback; removal may have partially completed before an error. This is a source-confirmed error-handling gap, not evidence these paths caused the route-wide P0. These paths also do not set shared busy while their own mutations run. Repair with bounded pending/error handling, retaining selection after failure and reconciling confirmed server state before claiming success.

4. **Auth failures generally fail closed, with limited recovery UX.** Parent initial session/dashboard chain is caught (`ParentApp.tsx:176-197`); act catches action/reload failures (`217-231`). Child library initial load is caught (`ChildLibrary.tsx:177-206`) and session revalidation disables access on uncertainty (`214-263`). ChildLogin catches picker bootstrap errors and redirects to login (`ChildLogin.tsx:58-76`), which can disguise a transient device/lock backend error as signed-out state. No source evidence justifies weakening authentication to resolve this. Parent shell retains its loaded snapshot after subsequent action auth failure; server mutations remain independently authenticated. Any cleanup should clear sensitive cached UI on positively confirmed role loss while retaining secure server checks.

5. **Provider callback secondary exception surface.** `ChildPlayer.tsx:469-490` protects identity checks through existing helpers but calls `e.target.destroy()` on ENDED without the try/catch used in other teardown paths. A provider SDK teardown exception would escape its event callback. This is a plausible exception surface, not a confirmed live failure. Preserve the existing stopped/completed/active state ordering and containment rules if making teardown best effort.
