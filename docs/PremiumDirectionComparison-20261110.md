# WatchNest — three internal experience directions

Prepared November 10, 2026. This is a prospective comparison for the renewed
Founder mandate, not a claim that three concepts were considered before the
November 4 implementation. Independent selection is required in a separate
receipt. No Founder concept approval is requested.

All directions retain the WatchNest mark, warm-family/premium-streaming intent,
real approved artwork, mandatory containment, individual-video approval, protected
Parent Mode, sibling isolation and existing backend. None changes the player.
All require 44px essential controls, keyboard/focus support, reduced motion and
readable feedback. Complexity estimates below are design judgments, not measured
usability or completed implementation evidence.

## A — Personal library and task-led family workspace

Child information architecture: a personal Home for a small resume/Recently Added
selection and shortcuts; Library is the complete searchable/sortable collection,
with Favorites and named Collections; Discover is explicitly request-only. Profile
identity and switch remain visible. A child can open an approved artwork tile
without navigating an editorial promotion. If Home has no meaningful distinction
for an empty or Simple profile, show a direct useful empty library path rather
than an intermediate welcome.

Parent layout: compact Family overview heading, actionable library/request counts,
then pending work and each child's library. Persistent Add videos belongs in the
header; no giant acquisition hero, slogans, duplicate sales CTA or decorative
thumbnail collage ahead of recurring work. Four labelled primary destinations
remain Overview, Library, Requests, Family. A request opens a concrete search or
approval task; approval and child assignment stay adjacent. Advanced management
is progressively disclosed under the relevant destination.

Visual grammar: ivory reading surface, evergreen selected navigation, amber for
restrained emphasis, artwork-led shelves, limited paper panels. Regular cards have
consistent image ratio and text beneath rather than text over busy artwork.
Phone uses stacked tasks and a small labelled navigation bar; iPad increases
browsing density without reducing targets. Desktop adds columns to related work,
not new navigation concepts.

Advantages: recognizable to both children and busy Parents; full-library retrieval
scales beyond hundreds of items; preserves already verified routes and much of the
existing design system. Risks: Home/Library redundancy must be actively rejected;
Parent overview must genuinely prioritize work, not become a renamed landing page.
Implementation: moderate incremental change over the preserved candidate, with
source-bound rendered review and actual recurring-task rechecks.

## B — Curator desk and persistent tablet rail

Child information architecture: one unified Browse surface with a persistent
portrait/landscape rail for All videos, Favorites and Collections; no separate Home.
Search is always in the content header. Selecting a Collection filters the same
workspace, making location and return state explicit. Profile switch sits at the
rail's top, with protected Parent access at its base.

Parent layout: desktop/tablet two-pane curator desk. Left pane is intake/search or
Inbox queue; right pane is selected video metadata, child assignments, Collection
and approval. A selected item remains in place while Parents process a sequence.
Phone turns the right pane into an explicit full-height review sheet with a sticky
single approval action and a clear back-to-results affordance. Time controls are a
separate child-focused rail destination rather than dashboard cards.

Visual grammar: warm neutral canvas, thin separators and compact rows; evergreen
rail and selected result, larger artwork in the inspection pane. Less ornamental
rounding; dense but calm alignment. No competitor sidebar identity is copied.

Advantages: efficient repeated curation; one browsing model; strong persistent
location on a wide iPad. Risks: the rail consumes scarce portrait content width;
phone sheet/selection/focus restoration raises interaction complexity; younger
children must understand filter location. Implementation: high change to front-end
state, focus and responsive navigation, requiring broad flow requalification even
though APIs and player remain unchanged.

## C — Collection-first child rooms and Parent task launcher

Child information architecture: profile picker leads directly to a picture-led
set of large Collection tiles plus All videos and Favorites. Opening a Collection
is a dedicated page with a clear back-to-Collections control. Recently Added lives
inside All videos rather than a separate Home. Search is exposed at the Collection
index and stays limited to approved items. Simple mode can prioritize fewer large
pictorial choices without changing approval boundaries.

Parent layout: phone-first task launcher with Add videos, Review requests, Manage
children and Time controls as four task entries. A shallow Library area manages
All videos and Collections; a compact inbox list precedes static totals. Desktop
keeps the same task hierarchy but exposes recent activity and family summaries
beside it, rather than becoming a different product.

Visual grammar: larger image-led Collection covers, warm tactile tile surfaces and
strong child identity. Color is restrained and meaningful; no emoji decoration,
no babyish palette, and no custom theme that hides text or security status.

Advantages: concrete spatial choices for younger children and clear Parent verbs.
Risks: poorly organized families face an extra collection choice before a video;
uncategorized content must not disappear; older children and large libraries still
need All videos/search, making index density important. Implementation: medium to
high IA change and likely additional collection-cover selection/fallback behavior;
existing family Collections must remain usable without new setup.

## Independent selection rubric

Assess each direction against the actual four-profile household and approved-only
promise, iPad portrait/landscape child autonomy, Parent-phone recurring tasks,
findability at hundreds of videos, accessibility/reach, distinctiveness without
noise, navigation/terminology consistency, implementation risk and preservation of
working ingestion/timer/security flows. Select one direction or a precisely bounded
combination; do not select by lowest cost alone or ask the Founder to choose.

The implementation and its prior PASS votes are not evidence that one concept is
best. Reviewers should separate proposal quality from current implementation
history. Any material selected change requires new exact-candidate evidence.
